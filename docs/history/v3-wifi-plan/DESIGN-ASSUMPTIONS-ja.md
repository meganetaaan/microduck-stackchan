# MicroDuck Stack chan 縦型Tab5案の設計前提と確認項目

更新日 2026年10月2日

実機が手元にないため、確認点が確定するまでは交換しやすい仮構成で設計を進めます。採用済みの外装・脚機構・Tab5位置を維持し、電源分岐と通信方式を仮置きします。本書は設計方針と確認順をまとめたもので、配線・通電・発注の確定仕様ではありません。

## 採用して進める仮構成

| 項目 | 今回の仮置き | まだ確定していないこと |
| --- | --- | --- |
| 外観 | カメラを上にした縦型Tab5、画面上半分の顔、前面接触部は平面 | 実物の背面細部、ねじのかかり代、印刷公差 |
| 機構 | 元の脚・関節・サーボ位置を維持する | 実機の製造版とシミュレーション形状の差 |
| 電源 | MicroDuckの保護・主スイッチ後の2S系統からTab5へ分岐する | 実際に使える分岐位置、コネクタ、保護動作、電流容量 |
| Tab5入力 | ExtPort2 J7のpin 1 GND、pin 2 SYS_VIN／HVIN 6–24 V。内蔵降圧回路を使う | 突入・ピーク消費、入力電圧の下限付近の挙動、自動起動 |
| 追加電源部品 | 別Tab5バッテリーと外付け降圧器は第一案に含めない | 実測により再検討する可能性 |
| 通信 | Wi-Fiで操作指示と状態を交換する | AP側、接続方式、アドレス解決、API、認証、再接続、通信断の扱い |
| 役割 | Tab5はUI、MicroDuck SoCは歩行制御を担当する | UIと実機制御APIをつなぐアダプターの実装 |

2Sであることだけで接続適合を確定しません。Tab5端子で、起動時やモーター負荷時も6–24 Vを維持できることを確認します。電池の電圧降下と配線の損失を含めて評価し、この入力範囲をバッテリーの低電圧停止閾値にそのまま置き換えません。保護・スイッチ・分岐位置・停止時の挙動も確認します。

## 電源と交換可能なハーネス

概念的な電源経路は次のとおりです。

1. MicroDuckの2Sバッテリー系
2. 機体既存の保護回路と主電源スイッチ
3. 定格未選定の分岐保護部品
4. ロボット側コネクタに合わせた交換可能な短い変換ハーネス
5. Tab5付属1.25 mmピッチ6ピンケーブル
6. Tab5 ExtPort2 J7のGND／HVIN入力

この順序は必要な機能の配置を表しています。現物にそのまま使える分岐端子があるとは仮定しません。主ハーネスや外装をコネクタ未確定のまま専用加工せず、ロボット側の短い変換部分を交換できる構成にします。

Tab5側はpin 1をGND、pin 2をSYS_VIN（HVIN）として扱います。残るpin 3/4のRS485 A/B、pin 5/6のSDA/SCLは使用せず、未接続の端末を1本ずつ絶縁します。コネクタシリーズ名、配線色、端子の向きを写真だけで推測しません。[S1][S2][S3]

Tab5回路図には入力側のFU4（1 A／30 Vのリセッタブルヒューズ）が示されていますが、これを分岐ハーネスのヒューズ定格や連続許容電流の根拠にはしません。

分岐ヒューズの電流値、線径、線長、接点容量、極性確認方法、保護方式はTBDです。Tab5の実際の突入電流と最大負荷、既存の電源系、ハーネス条件を確認して選びます。端子と絶縁は着脱できる箇所で保護し、配線を引っ張る力が基板コネクタへ直接かからないように固定する方針です。

## 外装内の仮配置

ボディは外形80 ×80 ×80 mm、名目壁厚2.4 mmです。単純な内側境界は75.2 mm四方ですが、角の丸み、ねじボス、取付ランド、支持部品が占めるため、その大きさの直方体が丸ごと収納できるという意味ではありません。

- 前面の中央開口は60 ×64 mm、R8。Tab5背面の部品や配線へのアクセス用に残す
- 側面開口は56 ×56 mm、R10。配線経路と着脱の候補として使い、コネクタ未確定の専用穴は追加しない
- ハーネスの余長と固定はボディ内の動かない部分へ寄せる。ねじ、背面カバー、取付ランド、放熱・端子アクセスを塞がないように実物で確認する
- 元の胴体からボディ内へ上がる線は、中央マウントと脚の動作範囲を避ける。最小約3.10 mmのクランプ周辺の隙間を配線用の空きとして使わない
- ケーブル径、曲げ半径、抜き差し方向、ストレインリリーフの位置が分かるまで、溝・穴・固定座の最終寸法は決めない

現在のSoC表現は8 ×65 ×30 mm、35 gの仮ブロックと支持台です。実際のRadxa基板、拡張基板、端子、放熱部品、ハーネスが収まることを示していません。公式の現行MicroDuck説明とシミュレーション資産のコンピューター形状には版の違いがあるため、入手する機体を確認してマウントだけを更新できるようにします。[S5]

今回の資料更新ではCAD、STL、質量、慣性、衝突形状を変更していません。配線や保護部品の重量・体積も新たにシミュレーションへ追加していません。確定後にはそれらを反映して再確認します。

## 通信と役割分担

Tab5は顔表示、ユーザー操作、状態表示をローカルで担当します。MicroDuckのSoCは関節・歩行制御と機体状態の判断を担当します。Wi-Fiでは歩行の開始・停止や目標状態などの上位指示、受理状態、機体状態を交換する方針です。関節の周期制御をWi-Fi越しにTab5へ移す設計にはしません。

MicroDuckの公開アーキテクチャ文書はドラフトであり、記載内容をそのまま利用できる現在のネットワークAPIとは見なしません。本試作でSoC内の制御インターフェースとTab5を接続するアダプター、メッセージ形式、順序・重複・タイムアウトの扱いは未実装です。[S6]

実装前に次を決めます。

- どちらがアクセスポイントになるか、または共通ネットワークを使うか
- 接続先の発見方法と、対象ロボットを取り違えない識別方法
- 指示の受理・完了・エラーを区別する応答
- 複数の操作元がある場合の制御権と、SoC側の通信監視・タイムアウト
- 通信断・Tab5再起動・SoC再起動の検出と、ローカル制御側の停止方針
- 再接続時に古い歩行指示を再実行しない扱い
- UIが未接続・停止・低電圧をどう表示するか

通信断時の具体的な関節出力や安全停止動作は、既存の歩行制御との整合を確認して決めます。Wi-Fi経由のUI停止ボタンだけで緊急停止機能が確立したとは扱いません。

## USBと電源終了処理

Radxa ZERO 3Wの資料ではUSBホスト出力は500 mAです。Tab5の主電源を賄えるとは仮定しません。普通のUSBケーブルには電源線があるため「データだけを接続した」とは扱いません。開発や保守でUSBを接続する際は、外部給電との併用条件と電源経路を確認します。USBとHVINの同時入力、逆流防止、起動の優先関係は未確認です。[S4]

MicroDuckの低電圧判定とシャットダウン実装は確認対象ですが、実際の分岐に対してどの時点で電源が切れるか、Tab5へ終了通知を出せるかは未確定です。SoCの停止、バッテリー保護回路の遮断、主スイッチ操作を同じものと見なしません。[S7]

Tab5公式資料は電源を切り離す前にシャットダウンするよう案内しており、突然の電源断後は再投入まで少なくとも5秒待つ注意があります。HVIN印加だけで期待どおり自動起動するかは未確認です。バッテリーを追加しない第一案で、必要な終了処理・瞬停・再起動動作を満たせるかを後で検証します。[S1]

## 確定へ進めるための確認表

| 確認対象 | 確認・測定する内容 | 結果を反映する場所 |
| --- | --- | --- |
| 入手する機体の版 | SoC、電源基板、バッテリー、保護回路、主スイッチ、元プレート | 使用部品表とSoC支持台 |
| 電源分岐 | 保護・主スイッチ後の取り出し位置、コネクタ、極性、接点容量 | 交換用ピッグテールと分岐保護 |
| Tab5負荷 | 起動、画面輝度、Wi-Fi通信などでの突入・ピーク・通常電流 | ヒューズ、線径、電源余裕 |
| 電圧と終了 | 負荷時の低下、低電圧判定、保護遮断、終了順序、HVIN再投入時の起動 | 電源構成と終了通知・再起動方針 |
| Tab5背面 | 部品の出張り、端子アクセス、M3穴の有効深さ、取付ランドとの当たり | ねじ長さ、接触面・逃げ |
| SoCと配線 | 基板・端子・放熱・曲げ半径・着脱に必要な空間 | 支持台とハーネス固定位置 |
| 印刷・締結 | 穴公差、ナット寸法、薄頭ねじの適合、クランプ荷重、回り止め | プリント条件と機械部品表 |
| 機構とケーブル | 歩行、足裏を接地したしゃがみ、座り／折りたたみ候補での引張り・挟み込み | ケーブル経路と再度の干渉確認 |
| 通信断・復帰 | 未接続、応答なし、重複指示、双方の再起動、古い指示の破棄 | 通信アダプターとTab5 UI |

未確認項目はTBDのまま管理し、実物がない間は外装穴、コネクタ、ねじ長さ、ヒューズ定格を確定扱いにしません。ソフトウェア側は、この仮構成を前提にUI・メッセージ仕様・状態遷移を検討できる段階です。

## 既存検証の範囲

保存済みの1,486姿勢・状態では追加部品と脚の接触はなく、10秒の歩行・待機も転倒しませんでした。これは保存済みモデルの結果です。未モデル化の配線・電装部品を含む実機、連続した全関節範囲、座り・折りたたみのバランス、印刷強度を保証するものではありません。元のSIT/FOLD候補姿勢にある床・脚同士の問題も解決済みとは扱いません。
