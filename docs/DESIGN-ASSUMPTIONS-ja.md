# MicroDuck Stack chan UARTアセンブリの設計前提

更新日 2026年10月2日

主案を3.3 V UART直結として進め、必要な部品と配線の仮配置を3Dアセンブリへ反映しました。Tab5はUI、MicroDuckのSoCは歩行制御を担当します。実機が手元にないため、公式情報から確かめた寸法と、未確定部品の外形・重量・配線経路を区別しています。

## 選択した構成

| 項目 | 主案 | 未確定事項 |
| --- | --- | --- |
| 通信 | Tab5とRadxaの3.3 V UARTをTX/RX/GNDの3本で接続 | UART有効化、ピン共用、HAT側の引出し、ボーレート、プロトコル |
| 代替通信 | 直結できない場合だけUSB-UART変換器を使う | 対応ドライバー、Radxa側USB接続、3.3 Vロジックの確認 |
| Tab5電源 | 保護・主スイッチ後のMicroDuck 2S系統からJ7 HVINへ分岐 | 取出口、コネクタ、電流、ヒューズ等、線径、低電圧停止 |
| 追加電源部品 | 外付け降圧器とTab5用追加バッテリーは主案に含めない | 負荷・起動・終了挙動で必要なら見直す |
| 外装 | 80 ×80 ×80 mm、縦型Tab5、カメラ上、顔は上半分、平面の取付部 | 実機背面との当たり、ねじかかり、印刷公差・強度 |
| 機構 | 元の脚・関節・サーボ位置を維持 | 実機版と公開シミュレーション資産の差 |

Wi-Fiは現在の主制御経路には使いません。前のWi-Fi仮案は`docs/history/v3-wifi-plan/`に残しています。USB-UARTも現在のアセンブリに重ねて常設していません。

## 信号と電源の対応

| 系統 | 起点 | 終点 |
| --- | --- | --- |
| UART TX | Tab5 M5-Bus物理pin 16、GPIO6をTXとして設定 | Radxa物理pin 16、UART4 RX_M1 |
| UART RX | Radxa物理pin 18、UART4 TX_M1 | Tab5 M5-Bus物理pin 15、GPIO7をRXとして設定 |
| 信号GND | Tab5 GND | Radxa／機体GNDと共通 |
| Tab5電源 | 機体の保護・主スイッチ後の2S分岐 | J7 pin 2 SYS_VIN、製品表記HVIN |
| Tab5電源GND | 同じ分岐のGND | J7 pin 1 GND |

物理ピン番号とGPIO番号は別です。UARTは3.3 Vロジックで、RS-232電圧や5 V UARTを接続する設計ではありません。信号3本に加えてTab5をUART端子から給電しません。J7の未使用pin 3/4のRS485 A/Bとpin 5/6のSDA/SCLは端末を1本ずつ絶縁します。配線色やピッチだけで極性・コネクタ系列を判断しません。[S1][S2][S3][S4]

Radxa側GPIOの位置をモデル上の線の終点から推定しません。モデルはヘッダー付近の引出し空間を表し、HATを接続したまま物理pin 16/18へアクセスできることまでは示していません。必要なら中継基板や引出しハーネスを設計します。

## 電源分岐と配線

仮の経路は、機体の2S系統、既存の保護・主スイッチ、分岐保護、交換可能な短い変換ハーネス、Tab5付属6Pケーブル、J7入力です。実機にそのまま使える分岐端子があるとは仮定しません。コネクタ未確定のまま主ハーネスを加工したり、専用コネクタ穴を外装へ固定したりしない構成です。

Tab5のHVIN入力範囲は6–24 Vです。起動時とモーター負荷時も、電池の電圧降下と配線損失を含めてこの範囲を保てることを確認します。この範囲を、そのまま機体の低電圧停止閾値にはしません。

Tab5回路図のFU4は1 A／30 Vのリセッタブルヒューズですが、これを分岐ハーネスのヒューズ定格や連続許容電流の根拠にはしません。分岐の保護方式、電流定格、線径、線長、接点容量はTBDです。Tab5の起動・画面・通信の実負荷と、既存の電源系を確認して選びます。[S2]

3Dモデルには実際の電源貫通穴とグロメットを設け、接続部をボディ内へ移しました。機体側の線の終端は分岐位置未確認の仮の受け渡し点です。線の長さ、曲げ半径、端末固定、引張力、機体既存の線との取り回しは実物に合わせて更新します。モデルの束径を、そのまま購入する線の規格には使いません。

## USBを代替にする場合

代替案は、RadxaのUSBホストへ3.3 V USB-UART変換器を接続し、変換器からTab5のUART端子へ信号3本を出す構成です。Tab5へUSBで主電源を供給する構成へ自動的に変更するものではありません。

Radxa ZERO 3Wの資料ではUSBホスト出力は500 mAです。Tab5の主電源を賄えるとは仮定しません。普通のUSBケーブルには電源線があるため「データだけを接続した」とも扱いません。開発・保守時も、USBとHVINの同時入力、逆流、起動優先、電源経路を別途確認します。[S5]

## 基板と取付の根拠

RadxaのPCB外形65 ×30 mm、厚さ1.6 mm、直径2.8 mmの4穴は公式CADから確認しました。穴中心はCAD上でわずかに非対称であり、一般的なPi Zeroの58 ×23 mmという仮定へ置き換えていません。参照したCAD版と製品図の端子位置には差があるため、コネクタの専用開口寸法は確定していません。

公式CAD全体の外形は約65.015 ×31.506 ×12.984 mmです。シミュレーションにはこれを覆う保守的な衝突外形を加えています。一方、表示用のチップ・コネクタ群は単純化しており、CADそのものを完全に再現した基板ではありません。元のCADには閉じていない面もあるため、質量をそのCAD体積から自動決定していません。[S4]

MicroDuckのRobot HATは維持する前提です。HATの正確な機械図と実重量がないため、Radxaとは別の仮の基板・部品空間・質量で表しています。基板支持、コネクタへのアクセス、放熱、絶縁、固定方法は実機で確認します。Radxa単体の外形が収まることを、HATを含む全構成の適合証明にはしません。[S6]

Tab5のM5-BusとJ7は背面方向へ差し込む端子です。位置は公式の背面図から読み取った目安であり、寸法指定された端子中心ではありません。カメラを上にしたときM5-Busが前面リムの下側に近づくため、差込部と配線が通る実際の逃げを追加しました。平面の取付ランドと外側の輪郭は維持しています。

## 通信ソフトウェアで決めること

UARTを選んだだけで制御ソフトウェアが接続済みになるわけではありません。Tab5は表示と操作、SoCは関節・歩行制御をローカルで担当し、UARTでは上位指示と状態を交換する方針です。関節の周期制御をTab5へ移す設計にはしません。

今後の実装で、UARTの有効化とピン設定、ボーレート、フレーム形式、誤り検出、指示ID、受理・完了・エラーの区別、再送、重複排除、通信監視・タイムアウトを決めます。双方の再起動や通信断後に古い歩行指示を再実行しないこと、複数の操作元がある場合の制御権も必要です。

MicroDuckの公開アーキテクチャ文書はドラフトであり、そのまま使えるTab5向けネットワーク／シリアルAPIが既にあるとは扱いません。本試作のUI連携アダプターは未実装です。通信断時の関節出力や停止動作は既存の歩行制御と合わせて決め、UIの停止ボタンだけで緊急停止機能が確立したとは扱いません。[S7]

## 電源終了と再投入

SoCの停止、機体の低電圧判定、バッテリー保護回路の遮断、主スイッチ操作を同じものと見なしません。Tab5へ終了通知を出せるか、どの時点で分岐の電源が切れるか、追加バッテリーなしで必要な終了処理を満たすかは未確定です。

Tab5公式資料は電源を切り離す前にシャットダウンするよう案内し、突然の電源断後は再投入まで少なくとも5秒待つ注意を示しています。HVIN印加だけで期待どおり自動起動するかも未確認です。[S1]

## 確認順

| 対象 | 確認する内容 | 更新するもの |
| --- | --- | --- |
| 機体の版 | SoC、HAT、電源基板、保護・スイッチ、元のプレート | 仮の機器外形・基板支持 |
| 分岐と負荷 | 取出口、極性、端子容量、起動ピーク、モーター負荷時の電圧 | ハーネス、ヒューズ等、線径 |
| UART | ピン共用、OS設定、3.3 V、HAT側アクセス、双方向通信 | 中継部とUI連携実装 |
| 終了動作 | 低電圧、電源断、SoCとTab5の終了順序、HVIN再投入 | 停止・再起動方針 |
| 取付 | Tab5のM3有効深さ、基板部品、ねじ頭、印刷公差 | ねじ全長、取付逃げ・支持 |
| 配線 | 曲げ・抜き差し、引張保持、放熱・カバーとの干渉、脚の動作範囲 | ガイド、固定部、線の長さ |
| 最終構成 | 実重量・重心と必要部品の追加 | MuJoCoモデルと学習・評価の再確認 |

現在の幾何確認は484状態であり、歩容学習の成功・実機での安全な運用・全可動域を保証するものではありません。詳細は[アセンブリREADME](../README-ASSEMBLY-UART-ja.md)と[検証報告](../prototype/assembly_uart/validation_report.json)を参照してください。
